# 万8基线冻结与指数增强组合优化运行手册

## 1. 本阶段解决的问题

本阶段先把实验口径固定，再优化从模型分数到真实持仓的过程：

1. 从 RQAlphaPlus 解析训练/回测入口最终生效的完整配置；
2. 固定佣金万8、时点印花税、滑点、资金、基准和调仓参数；
3. 冻结旧模型在统一费用下的基线，避免后续实验互相覆盖；
4. 用本地指数权重文件构造基准约束组合，降低跟踪误差和换手；
5. 保留完整配置、净值、交易和诊断文件，使每次结果可复现。

RQAlphaPlus 在本地运行，不使用代理。入口会在启动前清除大小写两套 HTTP、HTTPS、ALL_PROXY 和 NO_PROXY 环境变量。

## 2. RQAlphaPlus 配置留档

每个回测目录都会保存两份配置：

- `backtest_effective_config.json`：项目层最终参数、版本号和解析后的交易费用假设；
- `rqalpha_effective_config.json`：RQAlphaPlus `parse_config` 解析后的完整配置快照，敏感字段会被脱敏。

同时保存：

- `backtest_summary.json`：统一口径绩效摘要；
- `portfolio.csv`：组合与基准净值；
- `positions_weight.csv`：每日实际持仓权重；
- `trades.csv`：逐笔成交和费用；
- `summary.xlsx`、`equity_curve.png`、`backtest_result.pkl`。

默认费用口径：股票佣金倍率 1，即 RQAlpha 股票基准佣金万8；单笔最低佣金 5 元；`pit_tax=true`，因此 2023-08-28 起卖出印花税为万5；滑点为 0.001。

## 3. 冻结统一费用基线

配置文件为 `configs/fee_0008_baseline.yaml`。它登记五组历史实验和三组指数回测，并对实际成交费用进行审计。

```bash
/opt/miniconda3/envs/rqsdk/bin/python -m src.index_enhancement.freeze_fee_baseline \
  --config configs/fee_0008_baseline.yaml
```

输出目录：`experiments/fee_0008_baseline_20260729/`。

关键产物：

- `performance_summary.csv`：统一重算的收益、波动、跟踪误差和信息比率；
- `annual_performance.csv`：年度拆分；
- `turnover_cost.csv`：换手、成交金额和费用；
- `fee_audit.csv`：从成交记录反推实际佣金率和卖出印花税率；
- `baseline_manifest.json`：输入文件指纹、Git 状态、运行环境和基线清单；
- `backtest_report/`：冻结的原始报告副本。

当前 15 个被审计回测的佣金率中位数均为 0.0008，卖出印花税率中位数均为 0.0005。

## 4. 指数增强组合优化

配置文件为 `configs/index_enhancement.yaml`。三组指数分别使用已验证过的模型目录：

- 沪深300：`results_excess_top_weighted/index_enhancement/csi300`；
- 中证500：`results_lambdarank/index_enhancement/csi500`；
- 中证1000：`results_lambdarank/index_enhancement/csi1000`。

组合优化只读取本地 `data/index_weights.csv.gz`，不会重复调用 RQData。目标函数同时考虑预测分数、相对基准风险、换手惩罚和显式买卖成本，并执行以下硬约束：

- 总股票仓位为 `cash_buffer`；
- 单股相对基准主动权重不超过 `max_active_weight`；
- 单股目标权重不超过 `max_stock_weight`；
- 单次目标换手不超过 `max_rebalance_turnover`；
- 只使用信号日当时已经可见的指数权重。

运行全部指数：

```bash
/opt/miniconda3/envs/rqsdk/bin/python -m rqalpha_strategy.run_index_enhancement \
  --config configs/index_enhancement.yaml
```

仅运行单个指数：

```bash
/opt/miniconda3/envs/rqsdk/bin/python -m rqalpha_strategy.run_index_enhancement \
  --config configs/index_enhancement.yaml --indexes csi300
```

输出根目录为 `results/index_enhancement_optimizer_backtest/`。

## 5. 已完成的沪深300验证

2024-01-02 至 2026-07-17 的优化组合结果：总收益 48.71%，年化收益 16.92%，几何超额收益 12.66%，跟踪误差 2.67%，信息比率 1.62，最大回撤 14.92%，最大超额回撤 3.55%。累计交易费用 8.89 万元，占初始资金 0.89%。

相对于原 Top-weighted 组合，跟踪误差由约 14.75% 降至 2.67%，信息比率由约 0.55 升至 1.62，最大超额回撤由约 18.96% 降至 3.55%，费用由约 45.09 万元降至 8.89 万元。说明当前最显著的改进来自组合构建和换手控制，而不是单纯继续提高预测分数。

## 6. 已完成的中证500验证

中证500最终验证结果为：总收益61.99%，年化收益20.93%，几何超额收益17.05%，跟踪误差3.89%，信息比率1.68，最大回撤17.01%，最大超额回撤4.62%；累计交易费用12.92万元，占初始资金1.29%。指数换成分时若 SLSQP 到达迭代上限，会自动切换到投影梯度求解，并继续严格执行权重与换手约束。

## 7. 已完成的中证1000验证

中证1000最终验证结果为：总收益43.22%，年化收益15.20%，几何超额收益17.63%，跟踪误差6.22%，信息比率1.18，最大回撤24.45%，最大超额回撤6.55%；累计交易费用14.26万元，占初始资金1.43%。相较沪深300和中证500，其跟踪误差与回撤仍偏高，和当前300只候选仅覆盖约34%—43%的指数权重有关。

## 8. GFlowNet 候选池设置

`configs/training_config.yaml` 的 `pipeline.pool_size` 已设为 300；训练入口会读取该配置，命令行 `--pool-size` 只在显式传入时覆盖它。

这里增加的是训练后由策略网络采样的候选表达式数量，不是直接送入 LightGBM 的因子数量。最终入模数量仍由 AlphaEval 的 DPP 筛选参数控制。推荐先保持最终 50 个因子不变，用 300 个候选给 DPP 更大的去相关选择空间；只有当样本外 IC、分组单调性和指数增强信息比率同步改善时，再把最终因子数逐步提高到 60—80。

## 9. 参数调整顺序

建议一次只调整一类参数，并保留独立实验目录：

1. 先调 `alpha_strength` 与 `risk_aversion`，观察超额收益和跟踪误差的前沿；
2. 再调 `turnover_penalty` 与 `max_rebalance_turnover`，观察净超额和费用；
3. 再调 `max_active_weight`，确认风险预算是否过紧；
4. 最后才调整候选股票数和最终因子数。

每次比较至少同时检查：样本外 RankIC、五分组单调性、跟踪误差、信息比率、最大超额回撤、年化双边换手和交易费用。

## 10. 当前限制

当前风险项是相对指数权重的对角风险代理，还没有使用行业、风格和完整协方差矩阵；候选股票数小于完整指数成分数时，优化器跟踪的是候选集合内归一化后的基准。下一阶段应把完整基准底仓与 alpha 主动仓分离，并接入时点一致的行业、市值、Beta、波动率和流动性暴露。
